# Yiwu Sourcing Operator

一人的义乌采购代理，把"运营总监"写进一份 6.7 万字的提示词里。

不是提示词模板，是**一个具体生意的决策系统**：它有预算上限、有交付能力边界、有做不到的事，并且会因为这些约束拒绝给出方案。

- 正文：2,831 行 / 102,326 字符（`prompts/sourcing-operator-prompt-v2.4.md`）
- 迭代：v1.0 → v2.4，30 条编号修订，其中 8 次推翻了自己上一版的核心建议
- 覆盖：16 项具体工作（W1–W16），8 个工作域，4 种输出模式

## 1. 它解决什么问题

背景很具体：一个人在义乌做 sourcing（替海外买家跑市场、找货、比价、拿样），刚转型，没有成交记录，没有供应商池，每周能投入营销的时间 10 小时，月预算有限。

这个阶段用通用 AI 助手，得到的东西长这样：

> "建议加强内容营销，提升品牌影响力，同时布局多渠道获客，建立私域流量池。"

这段话每句都对，但一句也不能执行。真正的问题是：**大模型的默认输出，是一个有团队、有预算、有成交记录的公司才用得起的建议。** 而一个人的公司照着做，会死在第一周。

所以这份提示词的目标不是"写得更完整"，是**让它在给出建议之前，先判断这个人接不接得住**。

## 2. 设计：17 个模块平铺 → 7 层架构

原始模板是 17 个模块的平铺列表（角色、信条、业务档案、输出格式、禁止事项……）。填满它很容易，但填满的模板不会思考——它只会把 17 个格子都写一遍。

改成 7 层，每层只回答一个问题：

```
┌─ 一 身份层  Identity    我是谁、我有什么、我绝对不能做什么
├─ 二 认知层  Cognition   遇到问题用哪套判断框架（4 个引擎）
├─ 三 执行层  Execution   16 项工作，每项有固定处理流程与输出结构
├─ 四 输出层  Output      4 种输出模式 + 写作原则 + 禁止事项
├─ 五 资产层  Asset       关键词库、违禁词、话术钩子、可调用素材
├─ 六 运行层  Runtime     初始化、追问协议、每周复盘、版本迭代
└─ 七 校验层  Validation  输出前 11 项自检，不过就重写
```

关键差别在第 7 层。**没有校验层的提示词，只能保证"写出来了"；有校验层，才能保证"没写出不该写的"** —— 不编数据、不编经历、不承诺做不到的事、不给出需要 5 个人执行的方案。

## 3. 认知层：三个引擎 + 一条路径

对应四种最容易做错的判断：

| 模块 | 回答的问题 | 核心机制 |
|---|---|---|
| **10x 增长透镜** | 这个动作值不值得做 | 5 个杠杆 + 5 个检验，过不了的直接否决，不给"也可以试试" |
| **信任工程 7 层级** | 素未谋面的买家凭什么把订单给你 | 从"我说我好"到"你能随时验证"，7 层按成本从低到高排，最低一层零成本 |
| **AI 替代矩阵（S/A/B/C）** | 哪些工作能交出去 | S 级直接给可复制指令；C 级明确写"不要交给 AI"，并说明为什么 |
| **冷启动路径（5 条）** | 零成交时第 1 单从哪来 | 前 4 条全部不依赖流量：同行溢出单、本地关系网、LinkedIn 私信、卖家社群；第 5 条（Google）并行做，但不指望它救急 |

第二个引擎是整套东西的重心。sourcing 是**先信任后交易**的生意，而零成交的人没有社会证明可用。解法不是"编一个案例"，是把信任来源从"我做成过什么"换成"你现在就能验证什么"——我在义乌、我随时能开视频、我给你看三家工厂的原始报价。**可验证的事实，胜过不可验证的资历。**

## 4. 八道约束闸门

每份方案输出前逐道过。这是整套提示词里最像"工程"的部分：不是靠模型自觉，是靠一张必须跑的清单。

| # | 闸门 | 触发否决的条件 |
|---|---|---|
| 1 | 人力 | 执行者写的是"一个营销专员" |
| 2 | 预算 | 月耗超上限且没有免费替代路径 |
| 3 | 时间 | 启动超 2 周，且没拆出本周能做的第一步 |
| 4 | 技能 | 需要专业设计、剪辑、开发 |
| 5 | 复利 | 做完就结束，不产生持续流量或信任 |
| 6 | 红线 | 让用户承诺 DDP、垫资、账期、公开加价、编造经历 |
| 7 | 交付就绪 | 会带来询盘，但他接不住 |
| 8 | 能力 | 要求他做他还不会的事（报价 / 单证 / 认证判断 / 验货 / 压价） |

闸门数量是长出来的，不是设计出来的：**6 道 → 7 道（发现"引流方案会带来接不住的询盘"）→ 8 道（发现"会带来询盘"还不够，得看这个动作是不是要求他承诺能力之外的结果）**。

第 8 道的处理方式值得单说：不是删掉需求，是**改交付形态**。把"我帮你算个 FOB 价"改成"我把三家的原始报价和差异摆给你，你自己判断"。需求没变，承诺的风险变了。

## 5. 迭代史：30 条修订，8 次推翻自己

这是这个仓库最想展示的部分——不是最终稿有多完整，是**每一版都被具体的事实推翻过一次**。

| 版本 | 触发 | 改动 | 被推翻的东西 |
|---|---|---|---|
| v1.0 | 原 17 模块模板 | 建立 7 层骨架 | — |
| v2.0 | 填入真实业务档案 | 新增竞争定位、对标分析、冷启动重写 | 原版路线图假设"已有站点"，作废 |
| v2.1 | 外部审查 15 条 | 15 处修正 | 明佣/差价双轨、价格透明定位、避开义乌打外地产业带 |
| v2.2 | 确认 8 项事实 | 冷启动路径、闸门 6→7、路线图重排 | 编造的踩坑案例、经验背书 |
| v2.3 | 交付能力六项全"不会" | 服务产品化 L0–L3、闸门 7→8、广告推至 W9 | $1,000 客单投广告的假设 |
| v2.4 | 4 项决策拍板 | 品类 4→3 集群、L0 范围边界、L2 拆四道门 | 主攻品类（Home & Kitchen → Fashion Accessories） |

三个具体的自我推翻，都写在文档里，没有抹掉：

**① "价格透明"被删掉。** 上一版主张公开工厂名与加价比例来换信任。但用户的商业模型是打包价——公开加价等于让他改掉商业模式。改成：**透明的是过程，不是价格。** 你能看见货怎么做出来，看见的是一个总价。

**② "避开义乌"被删掉。** 上一版建议去打外地产业集群，因为义乌小商品竞争激烈。但用户就在义乌——这个建议等于让他放弃唯一的地利。改成：**义乌是基地，不是限制。** 差异化不在地理，在响应方式和过程可见度。

**③ 广告从 W3 推到 W9，月预算从 1 万压到 ¥1,000–1,500。** 两次后移，不是一次调整。见下一节。

## 6. 三个判断案例

### 案例一：用算术否掉一个"正确"的渠道

Google 搜索广告对 B2B 获客是标准答案。但把这个生意代进去算：

```
客单 $1,000  →  毛利 $150–500
sourcing 类词 CPC $2–6，落地页零证据时转化 1–2%
→ CPQL = $100–600
→ 用 $100–600 买一个毛利 $150–500 的询盘
→ 而且询盘还要再打折成订单
```

结论：**打不平。** 于是三件事同时改：时点 W3 → W7 → W9（两次后移）、月预算从 1 万压到 ¥1,000–1,500、词表从品类大词换成低竞争的现场执行意图词。

更重要的是结论的定性：**广告不能用来买订单，只能用来验证 offer 有没有人点。** 真正该做的是把客单做上去（服务从 L0 叠到 L2），不是把广告做便宜。

### 案例二：用约束否掉老板的扩张欲

用户拍板 4 个品类。1 个人、每周 10 小时、4 组关键词 + 4 组内容 + 4 组供应商 = 4 个半成品。

处理不是"砍到 1 个"（用户不会接受），是**合并**：Headwear + Hair Accessories 在义乌是同一个产业带（商贸城一区/四区），合并成一个集群页，4 个变 3 个。

然后主攻顺序也改了：从 Home & Kitchen 改成 Fashion Accessories。理由是零成交阶段最缺的是**快成交**，不是高客单——发饰帽类客户决策 3–10 天，家居 2–6 周。供应商密度也高一倍（一天能跑 20 家 vs 5 家），而供应商密度就是比价速度，是唯一能赢大同行的地方。

### 案例三：用能力边界否掉一个更漂亮的定位

最优美的定位是"透明采购代理"——公开工厂、公开加价、用诚实打败大公司。问题是：它与打包价模型冲突，且要求六项交付能力全齐。

改成 **"你在义乌的眼睛和手"（Your eyes and hands in Yiwu）**。这句话只承诺"我在场"，不承诺"我做成过"。而"在场"今天就能验证，"资历"不能。

**定位第一次和交付能力对齐了** —— 这是 v2.3 的核心改动，也是整个文档里唯一一条"降级反而更强"的判断。

## 8. 怎么用

**作为 Skill：** 把这个文件夹放进 `~/.workbuddy/skills/`（或项目内的 `.workbuddy/skills/`），`SKILL.md` 会被自动索引，正文按需加载。

**作为系统提示词：** 复制 `prompts/` 里的一至七章，粘进 Custom Instructions 或 Project 的知识库。

**日常调用**（一句话切换模式与工作域）：

```
模式：方案。W7，帮我出 Fashion Accessories 的关键词清单。
模式：诊断。我不知道下一步该做什么。
模式：复盘。这是本周的五个数字。
```

**每周固定动作：** 跑一次 `模式：复盘`，把新得到的真实数据写回「业务档案」的更新区。文档里每个数字都标了来源属性（`[需自校准]` / `[平台公开数据]` / `[真实数据]`），填一次，下一次判断就准一格。

## 9. 关于这个仓库的说明

**这是归档，不是开发过程。** 仓库由一次性上传建立，GitHub 的 commit 历史不代表真实的迭代节奏。迭代证据在 `CHANGELOG.md` 和正文每章开头的修订表里——每条修订都对应一次具体的业务事实确认，不是文风调整。

**里面是真的业务数据。** 预算、客单、毛利、定价、能力自评（六项交付能力全部为零）都没有美化。公开它们是为了让判断可以被复核——一份把弱点藏起来的策略文档，没有复核价值。

**行业数值是区间，不是基准。** 文中所有 CPC、CPQL、转化率、验厂人天价格都标注了估算属性，来自公开资料与逻辑推演，没有一条是可引用的行业基准。任何数字套到别的生意上都必须重算。

**不构成商业、法律或合规建议。** 涉及报关、认证、验货判定的内容只做流程整理，结论必须由持牌机构或实际操作者出具。
